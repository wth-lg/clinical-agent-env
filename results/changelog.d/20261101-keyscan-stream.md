- keyscan stream (builder-268): `pnpm keyscan --range <sha>` and `--history` read `git log -p` as a stream, line by line, instead of holding it in one string. The full history of main now prints about 606 MB, past the longest string V8 holds, so the old read threw ERR_STRING_TOO_LONG and exited 1, and the pre-push hook refused every new-branch push as if a key were found. Detection, labels, exit codes and output lines are unchanged (byte-identical to the old scan on ranges it could still read). Every scan error, including git exiting nonzero partway through the log or an unexpected exception, now prints 'keyscan error: ...' and exits 2; the hook still refuses on any nonzero exit and says 'keyscan error' apart from 'remove the key'. New tests scan a synthetic history of about 600 MB (a key in an early commit is found; a clean one exits 0) and a log that git abandons on a missing blob.
