- `pnpm cli classes <run>[,<run>...] [--json]` prints the class table from records (plan-amendment-w4 PW4-H0b). Per task: the PASS count and Wilson 95%, each trial's outcome, failed trials split model, environment, grader and infra, finish-guard fires, and q (of the trials where any event fired, those that saw every arrival). Per class and instance: fails out of trials x instances, pass rate, Wilson 95% and each failure's gate and auto label. Per event spec (tasks/<id>/events.ts SPECS and ACTIVE): fails out of the trials it fired in, the trials that saw it and the amend fails among them. Also outside-the-list failures and the independence table. On results/probe-1 it reproduces classes.md's class rows, outcome lines and independence table byte for byte. `--json` is ClassesJson, schema_version 1, the contract result-card reads. The item list comes from the checkout's expected.ts (an ITEM_CLASSES export, or each task's current shape), and a run that graded a different list exits 1. `pnpm cli events-solve` runs stop rules S-1 and S-2. It pools f, q and p_D with +0.5 smoothing, takes b_t from the base class fails, and computes pred_t(e) = q x b_t x (1 - f)^(e - 1) x p_D. A task above 0.70 at e_max freezes on v1. The other tasks' e* are solved together: every vector of counts meeting p90 <= $3.00 per task and mean p90 <= $2.40 is tried, and the least sum of squared distance from 0.45 wins. Each task gets the S-2 action: freeze on v1, 4 more trials on v1, or 8 trials on v2. `pnpm cli context-budget ... --project --items ... --events <id=e,...> --req-per-event <r>` projects each trial at T = 2 + k x n + r x e with its own k. On results/probe-1 at the pilot-4a lists (4 events, r = 3) the per-trial p90s are T1 $1.79, T2 $1.89, T3 $2.50, T4 $1.45, T5 $2.25 and T6 $2.17, mean $2.01.
