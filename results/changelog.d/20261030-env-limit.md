- Attribution split for stops (W0-A, builder-195): a trial that stops at the model's context window, or at a turn, cost or working-time cap that rule P-L does not find looping, is now ENV_LIMIT, the environment's fault, excluded from the valid denominator and never run again, because the same task stops the same way; it was a model LIMIT (or, for a context-window stop, a COMPLETED trial graded FAIL) before. This reverses R14-13 and R14-14 for caps reached without a loop. (1) A response with stop_reason `model_context_window_exceeded` ends the trial LIMIT `context_window` (code `stop_reason`) and runs none of its tool calls; a tool call cut off by that stop is dropped like one cut off at `max_tokens`, where it used to raise `invalid_tool_input` and re-queue as INFRA_API. (2) A 400 "prompt is too long" ends only its own trial, LIMIT `context_window` (code `prompt_too_long`), and no longer stops the batch. (3) Rule P-L (`packages/grader/progress.ts`) decides a cap stop from the trajectory and fails safe: a cap stop is the model's (LIMIT, MF2) only when half or more of the last 20 executed calls repeat an earlier call with the same tool and the same target (the input without free text or fields the tool does not declare; for a search, the same query and page). Every other cap stop is ENV_LIMIT, which halts the run, since every pilot and the final run require env_limit=0, so a human reviews each one: a model that pads its tail with new reads or writes ends there, never in the pass rate. Every 20-call window of every pilot-1 and pilot-2 trajectory (2030 windows) and the worklist shapes W1-W10 at every cut read as no loop; exact repeats (the same re-reads, a write loop on one target, one search word for word) read as looping. The grade records the P-L facts on a cap stop (`progress`), so the Runs list gives the trial page's reason. A second `max_tokens` stop in a row stays a model LIMIT. (4) New criteria E7 (context window) and E8 (cap stop with no loop, with the P-L facts as evidence); MF2 now reads "output limit, or a cap while looping". `NOT_RERUN_REASON` in `outcomes.ts` names the two outcomes never rerun (GRADER_ERROR and ENV_LIMIT) and why; DENOMINATOR_RULE, the web's "Not counted" line, the fault note on the trial page and in Runs, and the not-graded sentence read it. (5) `pnpm cli summary` counts `env_limit` per task and in the totals, and `--require env_limit=0` fails a run with any (summary.json schema 9).
