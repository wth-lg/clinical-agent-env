- `pnpm cli events-solve` and `pnpm cli context-budget --events` no longer count event requests twice when the cost source already contains event arrivals (PW4-H0b2). Before this change, `events-solve results/pilot-4a` fitted k from trials whose T already held about 4 x r event requests, and then added r x e again. Each trial's k is now fitted net of its own arrivals: k = (T - 2 - r x the env_event lines in its trajectory) / items. r is refit from those trials by least squares within each task, pooled over the tasks. The refit needs at least 5 trials whose arrival count differs from their task's most common count. The output prints r with its standard error. An explicit `--req-per-event` overrides the fit, and the output prints both values. When a cost source has arrivals, r cannot be fitted and no r is given, the command exits 2 and names the reason. A cost source without arrivals gives the same output as before; on results/probe-1 every output is byte for byte the same. `classes`, `events-solve` and `context-budget` read a repeated run directory once and print a warning to stderr. In `classes`, q is counted over every valid trial, as stop rule S states it. An event gate failure goes to the event that its check item or its check names. If neither names an event, an event_seen or event_delivered failure goes to an event only when that event was the only one that fired on the item. An event gate failure that no event takes goes to `unattributed_event_failures`. These failures count against q and as event failures in S-1. In `events-solve`, ties between vectors of event counts are now compared as numbers.
