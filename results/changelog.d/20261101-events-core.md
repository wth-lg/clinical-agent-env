- Mid-trial events, the event core (plan-amendment-w4 PW4-E1), TOOLS_VERSION 8 and GRADER_VERSION 18. A task can declare event specs in tasks/<id>/events.ts (`SPECS`, and the `ACTIVE` ids that fire). An active spec fires once, after the call by which its trigger first holds: a write about a given patient, or the exposure of given records. Its resources and one inbox Task enter the store between writes. They never take a write sequence number, never appear in any tool result, and never appear in the written_ids of the call that fired them or of an earlier call. A later write by the agent to an arrival, such as completing its inbox Task, is the agent's own: it is in that call's written_ids. finish answers CONFLICT when an event fired in the same model turn. Each firing is one `env_event` line in the trajectory, and replay must reproduce it. The specs come from the task alone: both TaskSources (Node and browser) import events.ts beside its text, and run, run-one, replay, regrade, judge-calibrate, the matrix, the worker host and the browser's grader validation Worker all read them from the task. events.ts is an env file, so a change to it moves env_version. On the grader side, arrivals are listed in `diff.arrived` and never in created, so an arrived document is never graded as the agent's note. The agent's later change to an arrival is in updated and status_changed, compared with the version that arrived, as for any other resource; no grade reads updated or status_changed. A task with active specs adds the event gates: `event_delivered`, `had_turn`, `event_seen`, `amended` (process when the amend was written before the arrival was seen), `amend_form` and `kept` (a lure). Each failed item names its spec. An undelivered arrival grades ENV_ERROR, under new criterion E9; an arrival in the model's last turn fails had_turn, under E10. The matrix requires every active spec to be graded by those gates, to have its near misses (no amend, never seen, amended before seen, acted on a lure), and to keep the arrived split in every case: no arrival in the written_ids of the call that fired it or of an earlier call, never in created, and in updated exactly when a later call wrote it. The trial page shows each arrival as a row after the step that fired it. The toy task carries two active specs, a new result and a lure, fired by opening a problem no existing toy script reads. It also gains update_inbox_item and an alternative that completes the arrival's inbox item; its no_other_writes gate allows a write to an arrival only after the arrival. Every earlier toy trajectory is unchanged apart from its version fields and the tool list of its first request, and every earlier toy grade is unchanged. No other task has events.ts, and with no active specs every results/probe-1 record grades to its grader-17 outcome, score and checks. Ruling R36: results-inbox's 7-day creatinine window and crc-care-gap's screening absences now count a sorted run of pages as complete once a page passes the window's edge, as message-queue did at grader 17. Each task has a new alternative that stops past the edge and a new mutant that stops short.
