- W5-H lever toggles, lever-item classes and the selector (builder-298, plan-amendment-w5). A task's lever items are toggles: tasks/<id>/expected.ts exports `LEVER`, the active item ids, as one literal list or re-exported from tasks/<id>/lever.ts, and `LEVER_ITEMS` (id, kind A or B, item, patient, spec for an A item's event, sibling records, gates); the task loader reads LEVER from the files' text and env_version covers it only when a task declares it, so every task's hash here is what it was. `pnpm cli classes` adds one row per lever item (catch = passed / observed, Wilson 95%, the retrieval / reasoning / process split, each failure's gates and label, how many observed trials exposed every sibling record) and base_pass for S5's b_t; a task without lever items prints what it printed, and pilot-4a and pilot-4b are byte-identical. New `pnpm cli lever-select` computes S5-2 (smoothed rates, the set nearest 0.45 inside [0.30, 0.60], a tie to the larger set, the freeze, reserve and S5-3 branches) and S5-6 over --p90, and says which toggles need fixtures:build (a B item is a static chart record, R40); an activated reserve joins the final set and its toggle, S5-3 changes no item (the nearest set is advisory), an exact one-size tie goes to the lower --item-cost then to the A item, and S5-6 takes --p90 for all four W5 tasks and drops one item from the highest-p90 task while the mean exceeds $2.40, each step printed (gate #212 rulings F4, F5). `pnpm cli context-budget --project --lever <task=A+B>` projects a set (an A adds one event, a B one list item). The matrix checks lever declarations before any case runs (every A item declares its sibling records) and runs two cases per active A item from tests/agents.ts `lever[<id>]`: focus-only must fail exactly that item as retrieval on a gate of the lever's own (its gates, or an event gate failing its spec) without exposing the sibling, read-all-newest must pass. classes counts a gates-declared item's other gate failures against base_pass, and exits 1 on a historical run whose pin has no lever table while the checkout declares LEVER_ITEMS (the pilot-5a pin must carry `lever`; `lever: null` marks an older run). No grader, world or task version moves.
